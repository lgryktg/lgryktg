# 多用户隔离补强记录

## 已有隔离基础

业务系统使用服务端登录会话和 AsyncLocalStorage 传递身份。usage 与 quotas 按 userId 保存；普通用户偏好加密存储；普通用户工作区和素材位于 data/users/<userId> 内。工作区解析基于规范化后的真实路径检查范围，普通用户不享受本机管理员的任意目录权限。

## 本次修改

- 用量读取缺少身份时拒绝；普通用户显式查询别人的 userId 时拒绝；用量结算与预留释放增加 userId 条件。
- 管理员按单个用户筛选时，待核对的预留记录也按同一用户过滤。
- 余额账户保存 ownerId，订阅前逐项校验；即使传入别人的有效账户 ID，也不能订阅该账户。
- FFmpeg 缺少依赖的通知按所属用户发送，避免向其他用户广播其操作通知。
- 素材分页游标绑定 ownerId，每个用户各保留最多四个游标，互不挤占分页配额。
- 缺少登录身份时拒绝工作区和素材入口访问。
- 未登录页面不读取或保存账号设置缓存。
- 登录、注册和退出后，通过同源 BroadcastChannel 和 storage 事件通知其他标签页重新加载；通知内容不包含身份、凭证或业务数据。
- 普通业务 API 的 Axios 请求携带页面身份标识，服务端与实际登录会话不一致时拒绝，防止旧页面跨账号保存数据。身份标识不能替代登录会话，也不能用于指定其他用户身份。
- 独立后台上线模式（NODE_ENV=production 或 ALLIN_ADMIN_REQUIRE_AUTH=1）要求至少 32 字符 ADMIN_TOKEN，否则拒绝启动。普通业务会话 Cookie 不具备独立后台访问权限。

隔离校验位于业务服务端；管理后台仍单独运行在 4318 端口，监控数据写入自己的 data 目录。没有把管理页面加入业务系统，也没有修改实际用户数据或创建演示用户。

依照原仓库规范没有新增测试模块、临时测试脚本、mock 用户或 fixture。当前没有两名真实普通用户的完整隔离验收结果，构建成功和未登录 401 不等于通过跨用户验收。

## 上线前仍需完成的验收

使用两个真实普通用户账号及一个管理员账号，分别核对：A 不能读取、下载、修改或删除 B 的项目、素材、会话；A 不能查询 B 的 Token 与额度；A 不能订阅 B 的余额；切换账号时其他标签页清除旧页面；管理员可按授权查看汇总。还需覆盖并发请求、长连接退出后的行为以及实际部署中的反向代理和管理后台权限。

当前版本采用同一服务与数据库中的逻辑隔离、按用户划分的文件目录，不是每个用户一套独立操作系统或独立数据库。多实例部署前还需处理现有进程内会话、订阅与文件锁的共享与失效机制。

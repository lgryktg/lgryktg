# AllinDream 独立数据管理中心 v0.3

## 本次新增：管理员专用用户运营功能

- 用户管理：分页查看全部普通注册账号，按邮箱、用户 ID、完整 IP、账号状态、使用侧重点筛选，支持用量排序与当前页 CSV 导出。
- 使用分析：按最近 24 小时 / 7 天 / 30 天 / 90 天 / 全部时间及模型统计；支持搜索单个用户或用户群体，展示生成类型占比、Token 分项、调用趋势和使用排行。
- 用户详情：账号资料、注册与最近登录 IP、用量与剩余额度；最近 90 天登录记录分页；当前周期最近 50 条调用元数据。
- 运营总览以注册用户、活跃用户与用量为中心；项目监控、任务、模型、成本、告警和系统监控继续保留。
- 采用与 AllinDream 漫剧系统一致的深蓝、青色、金色和原有品牌 Logo；管理后台仍独立运行。

上述用户统计直接查询完整用量账本，不受监控快照最近 10000 条限制。仅统计 users 表中的注册用户，不包含本机管理员。当前本机没有普通注册用户，因此页面显示真实的 0 与无记录状态，不添加演示用户。

## 已连接本机原系统

- 原系统：旁边的 Toonflow-app-master，服务地址 http://127.0.0.1:3000 。
- 独立后台：http://127.0.0.1:4318 。
- 默认每 10 秒采集，页面每 5 秒读取后台快照；浏览器关闭时，采集器仍随后台服务运行。
- 采集器只读取原系统文件及 SQLite 用量账本，不修改原系统源码、业务数据、密钥或配置。
- 后台自己的连接配置、告警、采样历史、管理审计保存在 allinAdmin/data/state.json。

原系统与后台分别启动、分别关闭。原系统停服时，后台仍能扫描已经落盘的工作区并显示服务离线告警。

## 启动

需要 Node.js 22.13 或更新版本；使用 Node 内置 SQLite，无第三方依赖。

双击 start.cmd，或在本目录执行：

    node server.mjs

如果页面已经能打开，不需要重复启动。端口已被占用时，先关闭原后台进程，再启动新版本。

可选配置：

    $env:PORT = '4318'
    $env:ADMIN_TOKEN = '自己的长随机管理令牌'
    node server.mjs

令牌只用于独立后台，在右上角“连接设置”填写。原系统不需要提供账号密码。后台仅监听本机 127.0.0.1，当前没有多用户权限体系，不应直接作为公网服务部署。

## 连接方式与独立边界

首次升级会自动识别同级 Toonflow-app-master。此后使用保存的连接配置；右上角“连接设置”可修改原系统目录、服务地址和采集周期，也可停止实时连接。支持原系统的标准 data 目录；原系统使用自定义 TOONFLOW_DATA_DIR 时需要再扩展连接配置，不会自动猜测其他数据位置。

仅支持本机 HTTP 根地址，不访问远程服务，不使用原系统登录会话，不输出或保存原系统 API Key。采集时读取 settings.json，以白名单提取项目登记、供应商标识与文本模型名称；不读取 accountEncryption.key、账号密码内容、加密的用户偏好或邮件正文。

SQLite 以 readOnly 打开，并使用 query_only 和短读事务读取完整一致的账本视图；不导入原系统数据库模块（该模块初始化时会执行建表与状态修正）。不执行供应商脚本或插件源码，不调用会产生生成费用的接口。

## 已接入的数据

| 数据域 | 来源与口径 |
| --- | --- |
| 在线状态与探测耗时 | GET /api/auth/status，不使用凭证 |
| 管理员项目 | settings 中项目登记 + data/workspaces，真实路径去重 |
| 成员工作区 | data/users/*/workspaces；不解密成员偏好，外部成员目录不在采集范围内 |
| 画布与节点 | 识别 toonflowCanvas=true 的 JSON，采集节点类型、标识与模型引用 |
| 本地素材 | 文件扩展名、大小及修改时间；目录图片/视频存量不等于生成任务量 |
| 素材引用 | 检查节点相对路径是否存在；不抓取远程素材，不访问越界路径或目录符号链接 |
| 用量记录 | accounts.sqlite/usage，最多最近 10000 条明细；另读取全表分组汇总和总数 |
| 成员及配额 | 监控快照提供数量与额度汇总；用户管理 API 单独以白名单读取用户 ID、注册邮箱、状态与登录 IP，不返回密码 |
| 模型 | 全局文本模型设置和画布中已引用的模型；用量模型单列，因账本缺少供应商 ID，不猜测其供应商 |
| 全局素材库 | data/assets 中的文件数量、扩展名与容量 |
| 安装项清单 | data/nodes、tools、providers、ext、skills 中的直接安装项数量，不执行代码 |
| 主机资源 | 整台电脑 CPU、内存、系统运行时间及原系统磁盘可用空间，不等同原系统进程占用 |

项目最多 256 个，每个项目最多扫描 50000 个目录项、12 层深度；单个画布 JSON 最大 16 MB。达到上限会显示采集警告。资产文件仅统计元数据，不读取图片或视频正文。

## 真实数据与未知值

usage 中 completed 显示已完成、pending 显示执行中、unknown 显示结果待核对、failed 才显示失败。unknown 不能当失败，pending 不能直接当作前端节点的实时生成状态。

当前源系统的 usage 表没有项目 ID、分镜 ID、结束时间、执行耗时、错误详情、人民币金额或审核状态。因此：

- 不能把系统级调用准确归属到项目。选择单个项目时，项目任务为空并说明原因。
- 没有数据时显示未采集，不显示假定金额 ¥0、完成百分比或虚构耗时。
- 节点是已保存的存量，不回推成历史生成任务；旧项目有节点但用量表为空是允许的。
- 未接入供应商账单与余额、原系统进程内存、浏览器临时状态、所有内部异常日志或第三方服务端执行队列。
- 若要覆盖上述数据，需要原系统补充可观测事件或正式只读监控接口；独立采集器不能恢复从未保存的历史字段。

统计周期按调用创建时间过滤，使用上海时间展示。项目存量、告警及系统状态不受周期筛选影响。用量明细达到上限时页面标明截断；筛选结果仅覆盖已载入的最近记录。系统观测期可达率按最近最多 360 次采集计算，采集间隔改变会影响覆盖的实际时长。

## 告警与可靠性

自动识别：原系统状态接口不可达、账本读取失败、采集失败、失效素材引用、磁盘可用空间不足 10%、采集不完整。

同一规则持续异常时保留原告警与确认状态；条件恢复后记录恢复事件，下次复发创建新告警。确认仅表示已知悉，不代表修复。采集失败保留上次成功数据，并明确标记过期，不回退成示例数据。首次尚未采集成功时显示错误，不显示示例。

保留最近 360 次采样、1000 条告警变化、5000 条管理操作；页面告警变化显示最近 50 条，管理审计显示最近 100 条。当前只在后台页面显示告警，不发送邮件或系统推送。

## 独立后台 API

所有 API 同源；设置了 ADMIN_TOKEN 时需 Authorization: Bearer <token>。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | /api/snapshot | 当前真实数据或离线快照、连接状态、监控历史、审计 |
| POST | /api/sync | 手动触发一轮采集；读取失败返回 503 |
| POST | /api/connection | 保存连接设置并立即采集，或以 enabled=false 停止连接 |
| POST | /api/alerts/acknowledge | 确认活动告警，请求体含 id |
| GET | /api/template | 下载离线数据示例模板 |
| POST | /api/import | 离线模式导入快照；实时连接期间返回 409 |
| POST | /api/demo | 离线模式切换示例；实时连接期间返回 409 |

连接参数示例：

    {
      "enabled": true,
      "systemRoot": "C:/Users/Administrator/Desktop/allin漫剧系统/Toonflow-app-master",
      "serviceUrl": "http://127.0.0.1:3000",
      "intervalSeconds": 10
    }

## 文件与验证

- systemCollector.mjs：只读采集器、状态探测和数据源校验。
- server.mjs：独立服务、定时采集、告警生命周期、原子存储。
- public/liveView.js：真实数据页面与监控覆盖说明。
- public/app.js：离线页面兼容、连接管理、自动刷新和公共交互。
- data/backups/：接入升级前后台源码备份。
- data/state.json：独立后台配置、监控历史与离线快照；运行时原子写入。

已有后台验证入口：node --test tests/admin.test.mjs 。接入升级另完成了手动验证：状态映射、素材引用异常、离线告警、未知费用、敏感值不进入输出、读取前后数据库一致、拒绝外部服务地址。

ALLIN_ADMIN_DATA_DIR 可指定后台自己的存储目录，不能放入原系统目录内部。后台停服后可备份整个 data 文件夹；不要编辑原系统数据库来改变后台显示结果。

## 多用户隔离与上线管理权限

普通用户在业务系统内只能查询登录身份对应的用量、工作区、素材和配置。独立后台属于管理员全局视角，不应作为普通用户的数据接口。上线时必须设置 NODE_ENV=production 或 ALLIN_ADMIN_REQUIRE_AUTH=1，并提供至少 32 字符的独立 ADMIN_TOKEN；缺少令牌时服务拒绝启动。业务用户的登录 Cookie 不能代替该管理令牌。反向代理应将管理后台放在单独的管理员入口。

本次隔离补强涉及业务系统自身的服务端权限校验（余额订阅归属、用量归属、工作区身份和素材分页），管理后台仍独立部署。没有新增付费或用户测试记录，也没有迁移既有数据。
